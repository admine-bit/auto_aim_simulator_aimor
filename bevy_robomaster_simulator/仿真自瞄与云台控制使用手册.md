# Daedalus 仿真、自瞄与云台控制使用手册

本文档说明如何启动 Daedalus 仿真器、连接 `imca_vision_26aim` 视觉程序、切换手动/自瞄模式，以及处理“开启自瞄后键盘不能控制云台”的情况。

## 1. 先给结论：自瞄开启后，手动云台输入会被屏蔽

这是当前仿真器的设计行为，不是云台通信故障。

当自瞄订阅开启时，仿真器会执行以下逻辑：

1. 忽略己方受控 Infantry 的方向键和手柄右摇杆云台输入。
2. 接收视觉程序通过 Talos 共享内存发送的云台目标。
3. 使用仿真器中的 PID 控制器驱动云台转动。
4. 当视觉程序没有目标时，删除自瞄跟踪器并保持当前云台角度；不会自动恢复手动控制。

因此，“自瞄目标丢失后方向键仍然没有反应”也是预期行为。要恢复手动控制，需要关闭自瞄订阅。

特别注意：如果仿真器进程是以 `DAEDALUS_AUTO_AIM=1` 启动的，环境变量会持续强制开启自瞄，按 `F5` 不能关闭它。此时必须停止并重新启动仿真器，且不要设置该变量。

## 2. 系统组成与进程职责

联调时有两个主要进程：

| 进程 | 作用 | 关键环境变量 |
|---|---|---|
| `daedalus` | 渲染战场、产生相机图像和位姿、执行云台 PID、接收 Talos 云台指令 | `DAEDALUS_AUTO_AIM=1` 强制开启自瞄 |
| `standard_mpc` 或其他视觉程序 | 从 Talos 读取图像，识别目标，计算云台指令并发送回仿真器 | `IMCA_TALOS_SIMULATOR=1` 使用 Talos 仿真输入输出 |

两者通过以下文件通信：

```text
/tmp/talos_ipc_meta
/tmp/talos_ipc_image_pool
```

`DAEDALUS_AUTO_AIM` 主要控制仿真器，`IMCA_TALOS_SIMULATOR` 主要控制视觉程序。不要只给视觉程序设置 `DAEDALUS_AUTO_AIM`，那不会改变仿真器的手动/自瞄状态。

## 3. 推荐的一键启动方式

### 3.1 自动自瞄模式

在仿真器目录执行：

```bash
cd /home/ad/Simulator_aimor/bevy_robomaster_simulator
./start_simulation.sh
```

脚本默认运行：

```text
仿真器：target/release/daedalus
视觉程序：../imca_vision_26aim/build/auto_aim_debug_mpc
视觉程序工作目录：../imca_vision_26aim
视觉程序参数：configs/sentry.yaml
```

脚本会等待 Talos 共享内存就绪，再启动视觉程序。若已有 `daedalus` 进程，脚本会复用它，不会重复启动。
默认关闭源码侧的 `detection`、`reprojection` OpenCV 调试窗口，避免调试窗口抢走仿真器的键盘焦点；如需查看源码调试画面，可执行：

```bash
IMCA_VISION_DEBUG_WINDOWS=1 ./start_simulation.sh
```

如果只想运行稳定版入口，可指定：

```bash
./start_simulation.sh \
  --program /home/ad/Simulator_aimor/imca_vision_26aim/build/standard_mpc \
  --workdir /home/ad/Simulator_aimor/imca_vision_26aim \
  --clear-args -- configs/sentry.yaml
```

### 3.2 手动云台模式

如果需要使用方向键或手柄手动控制己方 Infantry 云台：

```bash
cd /home/ad/Simulator_aimor/bevy_robomaster_simulator
./start_simulation.sh --no-auto-aim
```

如果终端已经有旧的 `daedalus` 在运行，脚本只能复用旧进程，不能改变它启动时的环境变量。此时应先回到旧仿真器终端按 `Ctrl+C` 退出，再执行上面的命令。

也可以通过环境变量关闭脚本的默认自瞄：

```bash
AUTO_AIM=0 ./start_simulation.sh
```

### 3.3 分终端启动方式

自动自瞄：

```bash
# 终端 A：必须把 DAEDALUS_AUTO_AIM 设置给仿真器
cd /home/ad/Simulator_aimor/bevy_robomaster_simulator
DAEDALUS_AUTO_AIM=1 cargo run --release

# 终端 B：启动视觉程序
cd /home/ad/Simulator_aimor/imca_vision_26aim
IMCA_TALOS_SIMULATOR=1 ./build/standard_mpc configs/sentry.yaml
```

手动云台：

```bash
# 终端 A：明确移除可能继承的强制自瞄变量
cd /home/ad/Simulator_aimor/bevy_robomaster_simulator
env -u DAEDALUS_AUTO_AIM cargo run --release

# 终端 B：视觉程序可以继续连接 Talos；也可以暂时不启动视觉程序
cd /home/ad/Simulator_aimor/imca_vision_26aim
IMCA_TALOS_SIMULATOR=1 ./build/standard_mpc configs/sentry.yaml
```

## 4. 键盘和手柄控制

### 4.1 己方 Infantry

| 功能 | 键盘 | 说明 |
|---|---|---|
| 前后左右移动 | `W` `A` `S` `D` | 控制己方底盘 |
| 云台左右旋转 | `←` `→` | 手动模式有效 |
| 云台俯仰 | `↑` `↓` | 手动模式有效 |
| 底盘持续旋转 | `Q` | 再按一次关闭 |
| 发射弹丸 | `Space` | 当前实现仍会读取本地发射输入 |
| 切换自瞄订阅 | `F5` | 仅在没有 `DAEDALUS_AUTO_AIM=1` 强制时可关闭 |
| 切换视角 | `F3` | 自由视角、第一人称、第三人称之间切换 |
| 调试信息 | `F4` | 显示/隐藏调试信息 |
| 截图 | `F2` | 保存当前画面 |
| 切换活动假人 | `Tab` | 多个假人时使用 |

### 4.2 假人 Infantry

| 功能 | 键盘 |
|---|---|
| 移动 | `I` `J` `K` `L` |
| 云台左右旋转 | `C` `B` |
| 云台俯仰 | `F` `V` |
| 底盘持续旋转 | `U` |

这里的假人云台控制和己方 Infantry 的自瞄屏蔽逻辑不同；“开启自瞄后方向键无效”主要指己方受控 Infantry 云台。

### 4.3 Xbox 兼容手柄

| 功能 | 手柄操作 |
|---|---|
| 己方移动 | 左摇杆 |
| 己方云台 | 右摇杆 |
| 精细云台控制 | 按住左扳机 |
| 加速 | 左摇杆按下 |
| 发射 | 右扳机 |
| 自瞄 | 按住右扳机第二段/RT2 |
| 关闭手柄自瞄 | 松开 RT2；但强制环境变量仍会保持自瞄 |
| 切换己方底盘旋转 | 左扳机按下 |
| 切换假人底盘旋转 | `Y` |
| 切换视角 | `View` |
| 切换假人 | `Start` |

### 4.4 控制窗口和活动机器人

按键必须发送给仿真器窗口。当前一键脚本默认不启动源码 OpenCV 调试窗口，但仍建议先点击 Daedalus 窗口一次确认焦点；如果控制的是假人而不是己方 Infantry，请按 `Tab` 切换活动假人。处于自由视角时，移动控制可能受视角系统影响，建议切换到第一人称或第三人称后再测试云台。

## 5. 自瞄的完整操作流程

### 步骤 1：确认仿真器启动成功

一键脚本应显示：

```text
Talos 共享内存已就绪
```

手工检查共享内存：

```bash
ls -lh /tmp/talos_ipc_meta /tmp/talos_ipc_image_pool
```

### 步骤 2：确认视觉程序连接成功

视觉程序日志中应出现类似信息：

```text
[Talos] Connected to simulator shared memory
[Gimbal] Using Talos simulator backend
```

如果没有这两类日志，先不要排查目标识别，优先检查启动顺序、工作目录和 `IMCA_TALOS_SIMULATOR=1`。

### 步骤 3：确认自瞄订阅状态

仿真器日志中：

```text
Auto-aim subscription is now ENABLED.
```

表示己方云台手动输入已被屏蔽，接下来等待视觉程序发送目标。

```text
Auto-aim subscription is now DISABLED.
```

表示恢复手动云台输入。若按 `F5` 后没有出现 `DISABLED`，优先检查仿真器是否以 `DAEDALUS_AUTO_AIM=1` 启动。

### 步骤 4：确认目标和指令链路

视觉程序需要在相机画面中识别到有效装甲板，并产生云台指令。仿真器接收到有效目标后，会创建或更新 PID 跟踪器；云台随后逐渐转向目标，而不是瞬间跳转。

目标暂时丢失时，云台会保持当前角度；这不是“自瞄没有接管”的异常，而是因为当前没有可跟踪目标。注意：仿真器状态栏中的 `total` 是发射弹丸总数，不是视觉识别目标数；目标识别数量请看视觉程序每秒输出的 `armors=... targets=...`。
若 `targets=0`，先用 `F5` 关闭自瞄并用方向键/WASD 转动或移动机器人，让敌方装甲板进入相机画面，再重新开启自瞄。
如果需要人工接管，请按 `F5` 关闭订阅，或重启为手动模式。

## 6. 自瞄和手动模式的切换方法

### 场景 A：没有强制环境变量

仿真器以普通方式启动：

```bash
cargo run --release
```

此时：

1. 按 `F5`：开启自瞄订阅，方向键不再控制己方云台。
2. 再按 `F5`：关闭自瞄订阅，方向键恢复控制。

### 场景 B：使用一键脚本默认启动

当前脚本默认开启 `DAEDALUS_AUTO_AIM=1`。此时不要依赖 `F5` 关闭自瞄，应执行：

```bash
# 先在仿真器窗口按 Ctrl+C 停止旧进程
./start_simulation.sh --no-auto-aim
```

### 场景 C：已经有旧仿真器被脚本复用

脚本会提示：

```text
已运行仿真器的环境变量不会被修改
```

这表示当前脚本不能替换旧进程的自瞄策略。关闭旧的 `daedalus` 后再启动，是最可靠的切换方法。

## 7. 启动项目外的视觉程序

脚本并不限定必须运行本项目的 `standard_mpc`。例如：

```bash
./start_simulation.sh \
  --program /opt/my_vision/bin/vision \
  --workdir /opt/my_vision \
  --clear-args -- config.yaml
```

参数说明：

| 参数 | 作用 |
|---|---|
| `--program PATH` | 指定可执行程序 |
| `--workdir DIR` | 指定程序工作目录；相对程序路径也相对于此目录解析 |
| `--arg VALUE` | 追加一个参数，可重复使用 |
| `--clear-args` | 清除默认的 `configs/sentry.yaml` |
| `--no-auto-aim` | 以手动云台模式启动仿真器 |
| `--simulator-dir DIR` | 指定仿真器项目目录 |
| `--simulator-bin PATH` | 指定已编译的 `daedalus` |
| `--` | 后面的内容全部作为视觉程序参数 |

Python 程序示例：

```bash
./start_simulation.sh \
  --program /usr/bin/python3 \
  --workdir /opt/my_vision \
  --clear-args -- /opt/my_vision/main.py --config config.yaml
```

也可以直接修改脚本顶部的配置：

```bash
PROGRAM_PATH="/opt/my_vision/bin/vision"
PROGRAM_WORKDIR="/opt/my_vision"
PROGRAM_ARGS=("config.yaml" "--camera" "talos")
```

## 8. 仿真参数调整

仿真器参数位于 `config.toml` 的 `[vehicle]` 和 `[vehicle.gimbal_pid.*]`：

```toml
[vehicle]
gimbal_rotation_speed = 3.0
gimbal_pitch_limit = 0.785

[vehicle.gimbal_pid.yaw]
kp = 50.0
ki = 0.0
kd = 0.1
max_rate = 100.0
```

- `gimbal_rotation_speed`：手动云台转速，单位为 rad/s。
- `gimbal_pitch_limit`：俯仰角限制，当前约为 ±45°。
- `kp`、`ki`、`kd`：自瞄 PID 参数。
- `max_rate`：自瞄最大角速度。

建议先确认通信和坐标方向正确，再调整 PID。若目标方向完全相反，应先检查视觉程序的坐标系和 pitch/yaw 符号，不要直接增大 PID。

## 9. 常见问题排查

| 现象 | 原因 | 处理方法 |
|---|---|---|
| 开启自瞄后方向键不能转己方云台 | 自瞄订阅会屏蔽手动输入 | 按 `F5` 关闭；若无效，停止仿真器后用 `--no-auto-aim` 重启 |
| 目标丢失后云台不再转动 | 没有有效目标时 PID 跟踪器被移除，云台保持当前位置 | 重新让目标进入视野，或关闭自瞄进入手动模式 |
| 按 `F5` 仍无法关闭自瞄 | 仿真器进程继承了 `DAEDALUS_AUTO_AIM=1` | 停止旧 `daedalus`，使用 `env -u DAEDALUS_AUTO_AIM cargo run --release` 或 `./start_simulation.sh --no-auto-aim` |
| 一键脚本提示复用旧仿真器 | 已有 `daedalus` 进程 | 回到旧进程终端按 `Ctrl+C`，再重新执行脚本 |
| 视觉程序无法连接 | 仿真器未启动、共享内存残留、环境变量或工作目录错误 | 先启动仿真器，确认两个 `/tmp/talos_ipc_*` 文件，再检查 `IMCA_TALOS_SIMULATOR=1` |
| 视觉程序有连接日志但云台不动 | 没有发送有效控制命令、没有识别目标，或仍处于手动模式 | 检查视觉程序日志和目标画面，再检查仿真器自瞄订阅日志 |
| 方向键完全无效 | 仿真器窗口未获得焦点，或当前控制的是假人 | 点击仿真器窗口，按 `Tab` 切换活动假人，切换到非自由视角 |
| 仿真器显示 `auto-aim=ON` 但云台不动 | 自瞄订阅已开启，但视觉程序可能没有有效 `targets`，或尚未发送有效目标指令 | 查看视觉程序的 `armors=... targets=...` 日志；有目标后应发送控制命令 |
| 启动后出现 `detection`/`reprojection` 窗口并导致键盘失焦 | 开启了源码调试窗口 | 默认已关闭；若设置了 `IMCA_VISION_DEBUG_WINDOWS=1`，改回 `0` 或取消该环境变量 |
| 云台运动方向相反 | 坐标系或 yaw/pitch 符号配置不匹配 | 先确认 Talos 坐标转换，再调整视觉程序坐标，不建议只修改 PID |
| 启动时报 ALSA/pkg-config 错误 | Cargo 回退构建需要系统 ALSA 开发包 | 优先使用已有 `target/release/daedalus`；若需重新编译，请安装对应系统开发依赖 |

## 10. 正确退出

- 一键脚本启动的客户端退出后，脚本会停止它本次启动的仿真器。
- 如果脚本复用了已经运行的仿真器，客户端退出不会停止那个仿真器。
- 手工启动时，分别在对应终端按 `Ctrl+C`。
- 不要使用 `rm -rf /tmp`；如需清理，只处理 `/tmp/talos_ipc_meta` 和 `/tmp/talos_ipc_image_pool`，并先确认没有 `daedalus` 或视觉程序正在使用它们。

## 11. 快速命令表

```bash
# 默认：自动自瞄
./start_simulation.sh

# 手动控制己方云台
./start_simulation.sh --no-auto-aim

# 外部程序，手动模式
./start_simulation.sh --no-auto-aim \
  --program /opt/my_vision/bin/vision \
  --workdir /opt/my_vision \
  --clear-args -- config.yaml

# 查看帮助
./start_simulation.sh --help
```
